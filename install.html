🟢 What's new in v1.5.17

v1.5.17 — gateway credentials on the phone itself: you no longer need the web app to create your SMS gateway username and password. The gateway app now has its own "SMS Gateway" section: type a username (e.g. smartbookly), tap Create / rotate gateway credentials, and the phone generates a strong password, shows it in a dialog, and stores it encrypted on the phone. Paste that username + password into any third-party service (like SmartBookly) and it can send SMS from this SIM through the OpenCall cloud — the same API as before: gateway_api_login → 24-hour token, or username+password on every call to gateway_api_send_sms. A Gateway status button shows whether the gateway is on and its sent/failed counters. Install over the previous build — no re-pairing needed.

v1.5.16 — SMS Gateway: the web app now has an 📡 SMS Gateway tab. Enable it, pick which of your paired phones sends the messages, and choose a username and password (or let the app generate one — the password is shown exactly once and only its hash is stored). Any third-party service can then send SMS from your real SIM the same way as sms-gate: log in with your credentials to get a 24-hour token, or just pass username+password on every request, and call gateway_api_send_sms. Sends go only to the device you selected (with an optional "any online device" fallback), are rate-limited to 120/minute, and every successful API call is logged in an activity log you can see in the web app. The phone app needs no update for this — install v1.5.16 to get the version bump; no re-pairing needed.

v1.5.15 — the full audit build: every line of the web app, the phone apps and the database was reviewed and 19 bugs fixed. On the web: a recording bug that doubled the far-end voice volume (the speaker tap was connected to the recording bus twice), a crash when the phone app's heartbeat channel closed (removeChannel(null)), a race that could start two recordings at once, a stale pairing-code list after re-pairing, a call timer that never started on accepted calls, a level-meter that kept running (leaking audio) after a call ended, honest guards on hang-up/bridge-join, and safer text escaping in buttons that copy codes and keys. On the phone: incoming-call reporting no longer stalls the Telecom binder thread (could freeze or crash the call screen), the correct Android "simulated ringing" state constant, native WebRTC memory leaks fixed (factory/EGL/track disposal), the audio bridge no longer dies silently when the screen rotates, the call mask overlay now updates the number on call-waiting, and the self-dial loop guard in the bridge flavor. Install this build over the previous one — no re-pairing needed.

v1.5.14 — the far-end voice fix: your phone reported "Set as phone app" was never granted — and it turned out the app was never eligible for that role (Android requires a dial intent handler the app didn't have), so the role screen silently did nothing. Without the role, Android kept the other person's voice on the phone's earpiece — it never reached the microphone, so you couldn't hear them on the computer and they weren't recorded, while your own voice worked fine. This build makes the role grantable, pins the loudspeaker with the modern setCommunicationDevice API as a fallback, and adds a live "their voice" level meter in the call panel (green = arriving, red = not reaching this device) plus a red in-call warning with the exact fix. After installing: open the app → "Set as phone app" → confirm → end and redial.

v1.5.13 — the two reported bugs are fixed: (1) Calls stay in the background on the phone — "Start gateway" now walks you through the two grants Android needs (Display over other apps + Set as phone app) instead of leaving them optional; the web app's Devices tab shows a ⚠️ warning when either is missing. No more stock dialer popping up on the phone during calls. (2) Recordings capture both voices — the bridge flavor now disables hardware echo cancellation (it was erasing the caller from the mic) and forces the loudspeaker route; a route-keeper re-pins the speaker every 2 s during the call so telecom can't flip it back to the earpiece mid-call.

v1.5.12 — your mic and speakers, over the internet: the web-app device's microphone is the call mic and its speakers play the caller — audio is transported over the internet (WebRTC with a TURN relay), so the phone can be in a completely different location. No Bluetooth pairing needed. The phone just dials from your SIM and relays audio through the internet tunnel — no phone dialer UI, no phone mic, no phone speaker. Talk, listen, mute, hold, end and record — all from the web app, and recordings capture both voices.

v1.5.11 recap — the two big fixes: (1) Web app no longer blinks — the page stopped rebuilding itself every time your phone sent a heartbeat; "last seen" now refreshes silently in place. (2) Audio bridge now actually connects — both the web app and the phone app previously relied on STUN only, which fails on most home Wi-Fi and mobile data, so the call audio stayed on the phone. A TURN relay is now built in on both sides, so the browser sends and receives the call audio and the call runs from your computer: end it, mute it, hold it from the web panel. If the bridge ever fails to connect, the web app now tells you honestly instead of staying silent.

v1.5.10a regression fixes: mute state no longer leaks between calls (call #2 always starts unmuted, in sync on phone + web); the Mute button on listen-only gateway calls shows an honest hint instead of a fake state; call-panel buttons keep their highlight in sync. The call mask is now call-shape aware: it says "Waiting for the computer to take this call…" at first, switches to "call running from your computer" only when the bridge is real, and switches to "Call active on this phone" if you answer on the handset — it never lies about where the call runs.

Your calls are now fully web-controlled — the phone is just a SIM radio: a full-screen call mask covers the stock dialer for the whole call (the phone shows "📞 Call active — this call is running from your computer" instead of the dialer UI); it auto-disappears when the call ends and never traps your taps. The old 12-second silent-dialer window is now 30 seconds and restarts on every call-state change, so the dialer can't sneak back mid-call.

Mute finally does what you expect: the big Mute button in the web call panel now mutes your microphone (browser mic) — exactly like internet calls — instead of muting the phone's mic (which was killing your own voice in the call). A separate secondary Mute phone mic button silences the phone's own microphone to cut room noise. Android reports which mute path applied (telecom vs bridge) so the web shows the truth.

Louder, clearer voice path: the gateway now auto-raises the phone's in-call (voice-call) volume to max when a call starts and restores it after — so your voice from the computer always reaches the far end at full strength even if the phone's volume slider was low. The web call panel and Devices tab now explain the acoustic bridge honestly ("your voice: computer mic → phone speaker → the call").

v1.5.9 recap: deep regression sweep (10 bugs — live timers, signaling race, focus loss…), full UI/UX refresh with Inter typography. v1.5.8 recap: laptop audio fixed (AEC off + speaker re-assert), floating call popup, both-voice recordings.

🚀 Install in 4 steps

1

Download the APK on your Android 8.0+ phone (recommended: Gateway for fully automatic SIM calls + SMS; Bridge only if you want the zero-permission tap-based fallback).

2

Open it. If the sensitive-data dialog appears on Gateway: tap More details → Install anyway (or register first, per the section above). Bridge never shows it.

3

In the web app open the Devices tab → Create pairing code → type the 6 digits into the app → Pair.

4

Gateway asks permissions one at a time — allow each (SMS, phone, mic). If a dialog never appears, tap Blocked at install? Open unblock guide right in the app (Auto Blocker / Play Protect are the usual cause), or grant them in Settings → Apps → OpenCall Gateway → Permissions. Then tap Start gateway (Gateway) or Start bridge (Bridge).

5

Bridge users: on the app's main screen enter your SIM number and tap Save SIM number — the web app then shows it under your device in the Devices tab.

No APK at all? The web app installs as a PWA (Chrome → ⋮ → Install / “Add to Home screen”) with zero Play Protect involvement — full internet calling, no SIM relay.

🛡️ If Android says “Blocked for your protection”

Since April 2026 this message comes from Google's new Android Developer Verifier. It appears for every APK whose developer isn't registered with Google — it is not a malware verdict, and no APK signature can turn it off. Apps you installed before that never saw this dialog because they came from registered developers. Here are your options:

1

Tap More details on the block dialog (small text link).

2

Tap Install anyway → OK. Takes 3 seconds, needed once per app.

3

Done — future updates with the same signature install without the dialog.

Auto Blocker is different from the verifier dialog above. It's Samsung's own switch (One UI 6+), it blocks silently — no “Install anyway” button, install just fails or the app installs crippled with no permission dialogs. If the quick bypass above did nothing on your Samsung, this is your blocker.

1

Open Settings → Security and privacy → Auto Blocker.

2

Turn Auto Blocker off while you install OpenCall Gateway — or keep it on and tap App allowed (allowed-apps list) and add OpenCall Gateway there.

3

Install the APK again. Now the permission dialogs (SMS, phone, mic) will actually appear when the app asks.

4

You can switch Auto Blocker back on after installing — OpenCall stays allowed. If you later re-install from scratch, repeat this once.
